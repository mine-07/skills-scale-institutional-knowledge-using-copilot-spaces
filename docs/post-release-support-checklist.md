# OctoAcme Post-Release Support & Operations Checklist

This checklist ensures smooth post-release operations, incident management, and feedback collection—key responsibilities of the Support Lead persona.

## Pre-Release Preparation
- [ ] Support team trained on new features
- [ ] Support documentation and FAQs completed
- [ ] Runbooks for known issues created
- [ ] Escalation paths and on-call rotations defined
- [ ] Support system (ticketing, monitoring) configured
- [ ] Customer communication templates prepared
- [ ] Incident response playbook reviewed
- [ ] Rollback procedure tested and documented

## Go-Live Activities (24-48 Hours)
- [ ] Deployment verification completed
- [ ] Smoke tests passed
- [ ] Critical path scenarios tested
- [ ] Monitoring dashboards active and alerting
- [ ] Support team on standby
- [ ] Customer announcements sent
- [ ] Initial telemetry reviewed (errors, latency, usage)
- [ ] Post-launch stakeholder sync completed

## Incident Triage & Escalation
- [ ] P1 incidents: Response within 15 minutes
- [ ] P2 incidents: Response within 1 hour
- [ ] P3 incidents: Acknowledged within 4 hours
- [ ] Root cause analysis initiated for critical issues
- [ ] Workarounds communicated to affected users
- [ ] Technical team engaged for complex issues
- [ ] Customer notifications sent (status, ETA, resolution)

## Feedback Collection & Analysis
- [ ] Support tickets reviewed daily
- [ ] Customer feedback surveys deployed
- [ ] Common issues and themes identified
- [ ] Feedback categorized (bugs, feature requests, improvements)
- [ ] Trends reported to Product Manager
- [ ] User support metrics tracked (response time, resolution time, CSAT)
- [ ] Top feedback items escalated to backlog

## Operations & Monitoring
- [ ] System health metrics monitored (uptime, latency, errors)
- [ ] Error logs reviewed for patterns
- [ ] Performance degradation investigated and reported
- [ ] Data quality/accuracy validated
- [ ] Security issues investigated if reported
- [ ] Usage analytics reviewed for unexpected behavior
- [ ] Capacity planning recommendations shared with ops team

## Weekly Review (First Month Post-Launch)
- [ ] Support team retrospective held
- [ ] Top 5 customer issues discussed
- [ ] Critical bugs prioritized for hotfix
- [ ] Non-critical bugs added to backlog
- [ ] Customer sentiment assessed
- [ ] Process improvements identified
- [ ] Roadmap refinements recommended based on feedback

## Stakeholder Communication
- [ ] Daily status updates (first week)
- [ ] Weekly summaries (ongoing)
- [ ] Critical incident notifications sent immediately
- [ ] Monthly support metrics report created
- [ ] Quarterly retrospective with Product & Engineering
- [ ] Customer testimonials/wins shared
- [ ] Lessons learned documented

## User Success & Adoption
- [ ] Onboarding documentation verified
- [ ] Training sessions offered to power users
- [ ] Best practices documented
- [ ] User community forum/Slack channel established (if applicable)
- [ ] Success stories collected and shared
- [ ] Customer advisory board feedback solicited
- [ ] Long-term product direction influenced by support insights
